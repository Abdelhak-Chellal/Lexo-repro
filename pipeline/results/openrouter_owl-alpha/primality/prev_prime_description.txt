# Algorithm Design: `prev_prime(n)`

## 1. Understanding the Test Suite

From the I/O pairs, I can observe:

| Input | Output | Pattern |
|-------|--------|---------|
| 3 | 2 | largest prime < 3 |
| 4 | 3 | largest prime < 4 |
| 5 | 3 | largest prime < 5 |
| 6 | 5 | largest prime < 6 |
| 7 | 5 | largest prime < 7 |
| 10 | 7 | largest prime < 10 |
| 100 | 97 | largest prime < 100 |
| 1000000 | 999983 | largest prime < 1000000 |

**The function returns the largest prime number strictly less than `n`.**

## 2. Problem Definition

**Problem:** Given an integer `n > 2`, find the largest prime number that is strictly less than `n`.

**Constraints:**
- Input must be an `int` (not float, not string, etc.)
- Input must be greater than 2
- Must handle large inputs efficiently (up to at least 1,000,000+)

## 3. Algorithm Design

```
FUNCTION prev_prime(n):
    
    // --- Input Validation ---
    IF type(n) is not int:
        RAISE error: "expect parameter n to be int"
    
    IF n <= 2:
        RAISE error: "expect parameter n to be larger than 2"
    
    // --- Core Logic ---
    // Start from n-1 and decrement until we find a prime
    candidate = n - 1
    
    WHILE candidate >= 2:
        IF is_prime(candidate):
            RETURN candidate
        candidate = candidate - 1
    
    // This line is theoretically unreachable for n > 2
    // since 2 is always prime


FUNCTION is_prime(num):
    
    IF num < 2:
        RETURN False
    
    IF num == 2:
        RETURN True
    
    IF num is even:
        RETURN False
    
    // Check odd divisors up to sqrt(num)
    FOR i FROM 3 TO sqrt(num) STEP 2:
        IF num % i == 0:
            RETURN False
    
    RETURN True
```

## 4. Edge Cases Handled

| Edge Case | Handling |
|-----------|----------|
| **Float input** (2.5) | Type check rejects non-int |
| **String input** ('hello') | Type check rejects non-int |
| **Boolean** (True) | `True` is subclass of int in Python, but value is 1 ≤ 2, so rejected |
| **n = 2** | Rejected (must be > 2) |
| **n = 1, 0, -5** | Rejected (must be > 2) |
| **Large n** (1,000,000) | Trial division up to √n is efficient enough |
| **n is prime** (e.g., n=7) | Returns the prime *before* n (5), not n itself |
| **n is even** (e.g., n=4) | Correctly finds 3 |
| **Consecutive primes** (n=6) | Correctly finds 5 |

## Complexity

- **Time:** O(√n) per primality check, with at most O(n) candidates in the worst case → **O(n√n)** worst case, but in practice primes are dense enough that very few candidates need checking.
- **Space:** **O(1)** — no auxiliary data structures needed.
