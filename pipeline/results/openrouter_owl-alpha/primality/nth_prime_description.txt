# Algorithm Design: `nth_prime(n)`

## 1. Understanding the Test Suite

The function `f(n)` returns the **n-th prime number** (0-indexed), where:
- `f(0) = 2` (the 0th prime is 2)
- `f(1) = 3` (the 1st prime is 3)
- `f(2) = 5` (the 2nd prime is 5)
- ...and so on.

### Input Validation Requirements:
| Input | Behavior |
|-------|----------|
| Negative integer (`-1`, `-5`) | Throw error: "int parameter must be positive or zero" |
| Float (`1.5`) | Throw error: "takes (1) int type parameter. Given: <class 'float'>" |
| String (`'3'`) | Throw error: "takes (1) int type parameter. Given: <class 'str'>" |
| Boolean (`True`, `False`) | Accepted — `True` → `f(1) = 3`, `False` → `f(0) = 2` |

> **Key insight on booleans**: In Python, `bool` is a subclass of `int`, so `True == 1` and `False == 0`. The function accepts booleans but rejects other non-int types.

---

## 2. Problem Analysis

**Core Problem**: Given a non-negative integer `n`, return the `n`-th prime number (0-indexed).

**Complexity Considerations**:
- For `n = 100`, the answer is `547`, so we need an efficient prime-finding method.
- The **Prime Number Theorem** tells us the n-th prime is approximately `n * ln(n)`. For `n=100`, this gives ~460, and the actual value is 547. We can use this to set an upper bound for a sieve.

---

## 3. Algorithm Design

### Step-by-Step Approach

```
FUNCTION nth_prime(n):

    // --- INPUT VALIDATION ---
    1. If type(n) is NOT int (excluding bool subclass):
           → Actually, check: if type(n) is bool, it's acceptable.
           → If type(n) is not int and not bool: raise TypeError
           → Simpler: check isinstance(n, bool) first, then isinstance(n, int)
           → If not isinstance(n, int): raise TypeError with message about type
    
    2. If n < 0:
           → Raise ValueError: "int parameter must be positive or zero"

    // --- FIND THE n-TH PRIME (0-indexed) ---
    3. We need to find the (n+1)-th prime in 1-indexed terms, 
       or equivalently, collect primes until we have n+1 of them.

    4. Use the Sieve of Eratosthenes with an upper bound:
       - For n >= 6: upper_bound = n * (ln(n) + ln(ln(n))) + 10  (safe overestimate)
       - For n < 6: upper_bound = 15 (covers primes up to 13)

    5. Apply Sieve of Eratosthenes up to upper_bound:
       a. Create boolean array `is_prime[0..upper_bound]`, initialize all to True
       b. Set is_prime[0] = is_prime[1] = False
       c. For i from 2 to sqrt(upper_bound):
            If is_prime[i] is True:
                Mark all multiples of i (from i*i to upper_bound) as False
       d. Collect all indices where is_prime[index] is True into a list `primes`

    6. If len(primes) <= n:
       → Increase upper_bound and repeat (safety fallback)

    7. Return primes[n]  (0-indexed access)
```

### Sieve of Eratosthenes Detail

```
SIEVE(limit):
    is_prime = [True] * (limit + 1)
    is_prime[0] = False
    is_prime[1] = False
    
    FOR i FROM 2 TO floor(sqrt(limit)):
        IF is_prime[i]:
            FOR j FROM i*i TO limit STEP i:
                is_prime[j] = False
    
    RETURN [i FOR i IN RANGE(limit + 1) IF is_prime[i]]
```

---

## 4. Edge Cases

| Edge Case | Handling |
|-----------|----------|
| `n = 0` | Returns 2 (first prime) |
| `n = 1` | Returns 3 |
| Very large `n` | Upper bound formula ensures sieve is large enough; fallback expansion if not |
| `n = True` (bool) | Treated as `n = 1`, returns 3 |
| `n = False` (bool) | Treated as `n = 0`, returns 2 |
| Negative input | ValueError raised |
| Non-int type (float, string) | TypeError raised with descriptive message |

## Summary

The function **`nth_prime(n)`** returns the **n-th prime number (0-indexed)** using the **Sieve of Eratosthenes** with a mathematically derived upper bound based on the Prime Number Theorem. It performs strict type validation (accepting `int` and `bool`, rejecting all other types) and range validation (rejecting negative values).
