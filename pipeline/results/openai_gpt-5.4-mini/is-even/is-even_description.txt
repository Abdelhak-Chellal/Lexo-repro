### 1) Understand the Test Suite

The function behaves like an **odd/even checker**, but with some important twists:

- It returns **True** for even numbers.
- It returns **False** for odd numbers.
- It accepts:
  - integers
  - numeric strings like `"2"`, `"-4"`, `"1e2"`, `"0x10"`
- It rejects:
  - non-numeric values
  - booleans
  - empty/blank strings
  - floats that are not whole integers
- It treats negative numbers normally by parity.
- It uses specific error messages depending on the type problem:
  - `"is-odd expects a number."`
  - `"is-odd expects an integer."`

So despite the name `is-odd`, the observed output is actually:

- `True` if the value is even
- `False` if the value is odd

---

### 2) Analyze the Problem

We need to design a function that determines whether a value represents an **even integer**, after validating and possibly parsing the input.

Key rules inferred:

#### Input acceptance
- If input is a number:
  - integers are accepted
  - floats are accepted only if they are mathematically whole numbers, but the test suite suggests:
    - `4.000000000000001` is rejected as not integer
    - `0.5`, `2.5` are rejected as not integer
- If input is a string:
  - it must parse to a valid number
  - numeric strings in decimal, scientific notation, and hex notation are accepted
  - blank strings are rejected as not a number
- Booleans are rejected as not numbers
- `None`, objects, arrays/lists, and missing args are rejected as not numbers

#### Output
- Return `True` for even integers
- Return `False` for odd integers

#### Errors
- If the input is not a number-like value at all: throw  
  `"is-odd expects a number."`
- If the input is numeric but not an integer: throw  
  `"is-odd expects an integer."`

---

### 3) Design the Algorithm

A suitable algorithm:

#### Step A: Validate argument presence
- If no argument is provided, throw `"is-odd expects a number."`

#### Step B: Reject booleans and non-number types
- If value is `True` or `False`, throw `"is-odd expects a number."`
- If value is `None`, object, list, etc., throw `"is-odd expects a number."`

#### Step C: Normalize strings
- If input is a string:
  - trim whitespace
  - if empty after trimming, throw `"is-odd expects a number."`
  - attempt to parse it as a number
    - accept formats like:
      - `"2"`
      - `"-4"`
      - `"1e2"`
      - `"0x10"`
  - if parsing fails, throw `"is-odd expects a number."`

#### Step D: Check numeric type
- If the resulting value is not numeric, throw `"is-odd expects a number."`

#### Step E: Check integer-ness
- If the value is not a whole integer:
  - for floats, check if `value` equals its integer truncation exactly
  - if not, throw `"is-odd expects an integer."`

#### Step F: Determine parity
- Return `True` if integer value modulo 2 equals 0
- Return `False` otherwise

---

### 4) Handle Edge Cases

#### Edge cases to explicitly handle:
- `0` → even → `True`
- negative integers:
  - `-2` → even → `True`
  - `-3` → odd → `False`
- large integers:
  - `1000000000000000` → even → `True`
- numeric strings with signs:
  - `"-4"` → `True`
- numeric strings in scientific notation:
  - `"1e2"` → `True`
- numeric strings in hex notation:
  - `"0x10"` → `True`
- floating-point near-integers:
  - `4.000000000000001` → reject as non-integer
- whitespace-only strings:
  - reject as not a number

---

## Concise Algorithm Description

1. Ensure one argument exists; otherwise throw `"is-odd expects a number."`
2. Reject booleans and non-number, non-string inputs with `"is-odd expects a number."`
3. If the input is a string:
   - trim it
   - if empty, throw `"is-odd expects a number."`
   - parse it into a number; if parsing fails, throw `"is-odd expects a number."`
4. If the parsed/received number is not an integer, throw `"is-odd expects an integer."`
5. Return `True` if the integer is even, else `False`.
