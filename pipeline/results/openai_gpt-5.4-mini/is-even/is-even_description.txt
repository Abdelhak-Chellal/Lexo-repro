### 1) Understand the Test Suite

The function behaves like a **parity checker**, but it is **not** checking “oddness” in the usual sense.  
From the examples:

- `0 -> True`
- `2 -> True`
- `-2 -> True`
- `10 -> True`
- `1 -> False`
- `3 -> False`
- `1001 -> False`

So the function returns **True for even numbers**, and **False for odd numbers**.

It also accepts several input forms:
- numbers like `2`, `-10`, `0`
- numeric strings like `'0'`, `'-2'`, `'2.0'`, `' 4 '`

It rejects:
- non-numeric inputs
- booleans
- empty strings
- arrays, objects, `None`
- non-integer numeric values like `1.5`, `'2.5'`

And it throws specific errors:
- **`is-odd expects a number`** for invalid non-number-like inputs
- **`is-odd expects an integer`** for numeric values that are not integers

### 2) Analyze the Problem

Despite the function name in the error message being `is-odd`, the behavior indicates:

> Return `True` if the input is an integer and even, otherwise `False` if it is an integer and odd.

If the input can be interpreted as a numeric value:
- if it is not an integer, throw `is-odd expects an integer`
- if it is an integer, return whether it is even

If the input cannot be interpreted as a number at all:
- throw `is-odd expects a number`

Important details inferred from tests:
- `True` and `False` are **not** treated as numbers
- String parsing should allow whitespace around numeric text
- String `'2.0'` should be accepted as integer-valued
- String `'2.5'` should be rejected as non-integer
- Very large integers within safe integer range should work

### 3) Design the Algorithm

#### High-level algorithm

1. **Validate type / parse input**
   - If input is a boolean, `null`, array, object, empty string, or any non-numeric value:
     - throw `is-odd expects a number`
   - If input is a string:
     - trim whitespace
     - attempt to parse as a number
     - if parsing fails, throw `is-odd expects a number`

2. **Check if the parsed value is finite**
   - If not finite, throw `is-odd expects a number`

3. **Check integer-ness**
   - If the value is numeric but not an integer:
     - throw `is-odd expects an integer`
   - Accept values like `2.0` because they are integer-valued

4. **Determine parity**
   - If integer modulo 2 is `0`, return `True`
   - Otherwise return `False`

---

### 4) Edge Cases

Handle these carefully:

- `0` → even → `True`
- negative even numbers like `-2` → `True`
- negative odd numbers like `-3` → `False`
- numeric strings with spaces like `' 4 '` → `True`
- `'2.0'` → should be treated as integer `2`
- `'2.5'` / `1.5` → throw `is-odd expects an integer`
- `True` / `False` → throw `is-odd expects a number`
- `None` / `[]` / `{}` / `''` → throw `is-odd expects a number`
- very large integers within safe range → parity should still work
