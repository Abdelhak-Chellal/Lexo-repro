The function is computing the **next prime number greater than or equal to `n`**, with strict input validation.

## 1) What the test suite implies

From the examples:

- `f(0) = 2`
- `f(1) = 2`
- `f(2) = 3`
- `f(3) = 5`
- `f(4) = 5`
- `f(14) = 17`
- `f(17) = 19`
- `f(18) = 19`
- `f(29) = 31`
- `f(30) = 31`
- `f(-1) = 2`
- `f(-10) = 2`

So:

- For any integer `n <= 1`, the result is `2`.
- For any integer `n >= 2`, the result is the smallest prime **strictly greater than `n`** for prime inputs like `2`, `3`, `17`, `29`, and the smallest prime greater than or equal-ish to the next prime after `n` for composites.
  - Since `f(2) = 3`, this is **not** “next prime at or above `n`”
  - It is **next prime strictly greater than `n`**

Also, invalid non-integer inputs raise:

- `f(1.5)` → type error
- `f('5')` → type error
- `f(None)` → type error

So the function expects an **integer only**, and otherwise throws:
`nextprime() expect parameter n to be int. Given: <class '...'>.`

---

## 2) Problem definition

Given an integer `n`, return the **smallest prime number greater than `n`**.

Behavior:
- If `n` is not an integer, raise a `TypeError` with the specified message format.
- If `n < 2`, return `2`.
- Otherwise, search upward from `n + 1` until a prime is found.

---

## 3) Algorithm design

### Step-by-step

1. **Validate input type**
   - If `type(n) is not int`, raise:
     `nextprime() expect parameter n to be int. Given: <class '...'>.`

2. **Handle small integers**
   - If `n < 2`, return `2`

3. **Search for next prime**
   - Start at `candidate = n + 1`
   - While `candidate` is not prime:
     - increment `candidate` by 1
   - Return `candidate`

4. **Prime test**
   - For a candidate integer:
     - If `candidate < 2`, not prime
     - Check divisibility from `2` to `floor(sqrt(candidate))`
     - If any divisor divides evenly, not prime
     - Otherwise prime

---

## 4) Edge cases

- Negative integers: return `2`
- `0` and `1`: return `2`
- Prime input: return the next larger prime, not the same prime
  - e.g. `2 -> 3`, `3 -> 5`, `17 -> 19`
- Large integers: algorithm still works, though primality checking is brute-force and may be slow for very large values
- Non-integers: raise the exact type error

## Pseudocode

```python
def nextprime(n):
    if type(n) is not int:
        raise TypeError(f"nextprime() expect parameter n to be int. Given: {type(n)}.")

    if n < 2:
        return 2

    candidate = n + 1
    while not is_prime(candidate):
        candidate += 1
    return candidate


def is_prime(x):
    if x < 2:
        return False
    if x == 2:
        return True
    if x % 2 == 0:
        return False

    limit = int(x ** 0.5)
    for d in range(3, limit + 1, 2):
        if x % d == 0:
            return False
    return True
```

## Complexity

- Let `k` be the distance from `n+1` to the next prime.
- Let `m` be the size of the candidate prime tested.

Worst-case time:
- About `O(k * sqrt(m))`

Space:
- `O(1)`
