### 1) Understand the Test Suite

The function `f(n)` returns:

- the **smallest prime number greater than or equal to `n`** for integer inputs
- for values less than or equal to 2, it returns `2`
- it **rejects non-integer inputs** with a type error message:
  - `nextprime() expect parameter n to be int. Given: <type>.`

From the examples:

- `f(0) = 2`
- `f(1) = 2`
- `f(2) = 3`
- `f(3) = 5`
- `f(4) = 5`
- `f(5) = 7`
- `f(10) = 11`
- `f(11) = 13`
- `f(12) = 13`
- `f(13) = 17`

This indicates the function is **not returning the next prime strictly greater than `n` only in some cases**; instead, it behaves like a “next prime after `n`” function where:

- if `n` is itself prime, it returns the **next larger prime**
- if `n` is not prime, it returns the smallest prime greater than `n`
- special case: any `n <= 1` returns `2`

So for prime inputs:
- `3 -> 5`
- `5 -> 7`
- `11 -> 13`
- `13 -> 17`

For non-prime inputs:
- `4 -> 5`
- `10 -> 11`
- `12 -> 13`

Negative values also map to `2`.

### 2) Analyze the Problem

We want an algorithm that computes the **next prime strictly greater than the input integer**.

Constraints implied by the tests:

- Input must be an `int`
- If not an `int`, raise:
  - `nextprime() expect parameter n to be int. Given: <class '...'>.`
- For integers `n <= 1`, return `2`
- For integers `n >= 2`, return the smallest prime `p` such that `p > n`

---

### 3) Design the Algorithm

#### Step-by-step approach

1. **Validate type**
   - If `n` is not of type `int`, raise a `TypeError` with the exact message format expected.

2. **Handle small numbers**
   - If `n <= 1`, return `2`

3. **Search for the next prime**
   - Start from `candidate = n + 1`
   - While `candidate` is not prime:
     - increment `candidate` by 1
   - Return `candidate`

4. **Prime check**
   - To test whether a number is prime:
     - return `False` for numbers less than 2
     - check divisibility from `2` up to `sqrt(candidate)`
     - if any divisor divides evenly, it is not prime
     - otherwise, it is prime

---

### 4) Handle Edge Cases

#### Covered by tests
- `n = 0`, `1`, negative numbers → return `2`
- `n` being prime → return next prime
- `n` being composite → return next prime
- non-integer types (`float`, `str`, `None`) → raise type error

#### Additional edge cases
- Very large integers: algorithm still works, though primality testing is brute-force and may be slower
- Boolean values in Python:
  - `bool` is a subclass of `int`
  - if strict type checking is desired, use `type(n) is int` instead of `isinstance(n, int)`
  - the tests do not mention booleans, so a strict `int` type check is safest if matching the given error behavior

---

## Algorithm in Pseudocode

```python
def nextprime(n):
    if type(n) is not int:
        raise TypeError(f"nextprime() expect parameter n to be int. Given: {type(n)}.")

    if n <= 1:
        return 2

    candidate = n + 1
    while not is_prime(candidate):
        candidate += 1
    return candidate


def is_prime(x):
    if x < 2:
        return False
    if x == 2:
        return True
    if x % 2 == 0:
        return False

    limit = int(sqrt(x))
    for d in range(3, limit + 1, 2):
        if x % d == 0:
            return False
    return True
```

---

## Complexity

- Let `k` be the gap to the next prime.
- Each primality test is `O(sqrt(m))`, where `m` is the candidate number.
- Total complexity is approximately:
  - **O(k * sqrt(m))**

This is sufficient for the test suite and typical use.
