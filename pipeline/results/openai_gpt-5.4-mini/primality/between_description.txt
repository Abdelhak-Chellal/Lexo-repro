## 2) Analyze the Problem

### Problem definition
Given two integers `m` and `n`, return a list of all prime numbers `p` such that:

- `m <= p <= n`
- `p` is prime
- Results are in increasing order

### Constraints implied by tests
- Inputs must be strictly of type `int`
- Range can be:
  - normal (`m <= n`)
  - reversed (`m > n`) → return `[]`
  - negative → ignore values below 2
- Need inclusive bounds

## 3) Design the Algorithm

### Step-by-step approach
1. Validate input types:
   - if `m` is not `int`, raise:
     `"between() expect parameter m to be int. Given: <class 'TYPE'>."`
   - if `n` is not `int`, raise:
     `"between() expect parameter n to be int. Given: <class 'TYPE'>."`

2. Handle empty range:
   - if `m > n`, return `[]`

3. Determine the lower bound for primes:
   - primes start at `2`
   - so use `start = max(m, 2)`

4. Generate primes in `[start, n]`
   - For each number `x` in this interval:
     - check if `x` is prime
     - if yes, append to result

### Primality check
To test if `x` is prime:
- return `False` if `x < 2`
- return `True` if `x == 2`
- return `False` if `x` is even
- otherwise test odd divisors from `3` up to `sqrt(x)`

### Complexity
If using direct primality testing for each number:
- Time: roughly `O((n - m) * sqrt(n))`
- Space: `O(k)` for output, where `k` is the number of primes found

If efficiency matters for larger ranges, a sieve-based approach could be used, but the tests do not require it.

## 4) Handle Edge Cases

### Edge cases covered by tests
- `m > n` → return `[]`
- negative ranges → only primes ≥ 2 are returned
- same start and end:
  - prime → singleton list
  - non-prime → `[]`
- non-integer `m` or `n` → raise exact type error

### Additional edge cases
- `m = 1, n = 1` → `[]`
- `m = 2, n = 2` → `[2]`
- `m = 0, n = 1` → `[]`
- very large ranges: algorithm still works, though sieve may be faster if needed

**Function `f(m, n)` returns all prime numbers in the inclusive interval `[m, n]`.**
