### 1) Understand the test suite

The function `f(m, n)` returns a **list of prime numbers in the inclusive interval** from `m` to `n`.

From the examples:

- `f(0, 0) = []` → no primes at 0
- `f(0, 2) = [2]`
- `f(1, 10) = [2, 3, 5, 7]`
- `f(2, 2) = [2]`
- `f(3, 10) = [3, 5, 7]`
- `f(4, 20) = [5, 7, 11, 13, 17, 19]`
- `f(-5, 5) = [2, 3, 5]` → negative lower bounds are treated as starting from 2, since primes are positive integers > 1
- `f(10, 1) = []` → if the interval is reversed, return empty list

Input validation:
- `m` and `n` must be integers
- If either is not an int, raise an error like:
  - `between() expect parameter m to be int. Given: <class 'str'>.`
  - similarly for `n`

### 2) Analyze the problem

This is the classic problem of finding **all primes in a range** `[m, n]`.

Important observations:
- Primes are integers greater than 1.
- If `m > n`, result is empty.
- If `n < 2`, result is empty.
- If `m < 2`, the effective lower bound is `2`.
- Need strict type checking: only `int` accepted.

Complexity goal:
- A straightforward approach is testing each number for primality.
- A more efficient approach is using the **Sieve of Eratosthenes** on the interval up to `n`, then filtering from `m` to `n`.

---

### 3) Design the algorithm

#### Step-by-step approach

1. **Validate input types**
   - If `m` is not an `int`, raise:
     - `between() expect parameter m to be int. Given: <type>.`
   - If `n` is not an `int`, raise:
     - `between() expect parameter n to be int. Given: <type>.`

2. **Handle empty-range cases**
   - If `m > n`, return `[]`
   - If `n < 2`, return `[]`

3. **Normalize the lower bound**
   - Set `start = max(m, 2)`

4. **Find primes up to `n`**
   - Build a boolean array `is_prime[0..n]`
   - Initialize all as `True`, then mark `0` and `1` as `False`
   - For each `p` from `2` to `sqrt(n)`:
     - If `is_prime[p]` is `True`, mark multiples from `p*p` to `n` as `False`

5. **Collect results**
   - Return all numbers `x` in `[start, n]` where `is_prime[x]` is `True`

---

### 4) Handle edge cases

- `m == n`
  - Return `[m]` if `m` is prime, else `[]`
- `m < 0`
  - Treat as starting from `2`
- `n < 2`
  - No primes exist, return `[]`
- `m > n`
  - Return `[]`
- Non-integer inputs (`str`, `float`, `None`)
  - Raise the specified type error

---

### Pseudocode

```python
def f(m, n):
    if not isinstance(m, int):
        raise TypeError(f"between() expect parameter m to be int. Given: {type(m)}.")
    if not isinstance(n, int):
        raise TypeError(f"between() expect parameter n to be int. Given: {type(n)}.")

    if m > n or n < 2:
        return []

    start = max(m, 2)

    is_prime = [True] * (n + 1)
    is_prime[0] = False
    if n >= 1:
        is_prime[1] = False

    limit = int(n ** 0.5)
    for p in range(2, limit + 1):
        if is_prime[p]:
            for multiple in range(p * p, n + 1, p):
                is_prime[multiple] = False

    return [x for x in range(start, n + 1) if is_prime[x]]
```

---

### Final algorithm summary

The function validates that both inputs are integers, then returns all prime numbers in the inclusive range `[m, n]`. It uses the Sieve of Eratosthenes for efficient prime generation, handles negative or too-small bounds by starting from 2, returns an empty list for invalid intervals, and raises type errors for non-integer inputs.
