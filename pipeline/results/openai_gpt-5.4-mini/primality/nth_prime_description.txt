# Algorithm design

## Problem definition
Given a non-negative integer `n`, return the `(n+1)`-th prime number.

Because indexing starts at 0:
- `n = 0` → first prime = 2
- `n = 1` → second prime = 3

---

## Step-by-step algorithm

### 1. Validate type
Check whether the input is an integer-like value accepted by the function.

- If the input is not of type `int` or `bool`, raise a type error:
  - `"nth_prime() takes (1) int type parameter. Given: <class '...'>."`

Note:
- In Python, `bool` is a subclass of `int`, so `True` and `False` should be allowed.

### 2. Validate value
If the input integer is negative, raise:
- `"nth_prime() int parameter must be positive or zero."`

### 3. Find the n-th prime
Use a loop to generate primes in increasing order until the `(n+1)`-th prime is found.

A simple way:
- Start from `2`
- For each candidate number:
  - test whether it is prime
  - if prime, increment a prime counter
  - when the counter reaches `n + 1`, return that candidate

### 4. Prime test
To test whether a candidate is prime:
- `2` is prime
- numbers less than `2` are not prime
- otherwise, try dividing by integers from `2` up to `sqrt(candidate)`
- if any divisor divides evenly, it is not prime

---

# Pseudocode

```python
def nth_prime(n):
    # Type check
    if not isinstance(n, int):
        raise TypeError(f"nth_prime() takes (1) int type parameter. Given: {type(n)}.")

    # Value check
    if n < 0:
        raise ValueError("nth_prime() int parameter must be positive or zero.")

    def is_prime(x):
        if x < 2:
            return False
        if x == 2:
            return True
        if x % 2 == 0:
            return False
        d = 3
        while d * d <= x:
            if x % d == 0:
                return False
            d += 2
        return True

    count = -1
    candidate = 1
    while count < n:
        candidate += 1
        if is_prime(candidate):
            count += 1

    return candidate
```

# Edge cases to handle

1. **`n = 0`**
   - Must return `2`

2. **`n = 1`**
   - Must return `3`

3. **Boolean inputs**
   - `False` should behave like `0`
   - `True` should behave like `1`

4. **Non-integer numeric types**
   - `1.0` and `1.5` should be rejected if strict integer typing is required by the tests
   - The test suite explicitly rejects `1.5`

5. **Large inputs**
   - The simple prime-search loop works, but can be slow for large `n`
   - For better performance, a sieve-based approach could be used if needed

# Complexity

For the straightforward implementation:

- Let `p` be the `(n+1)`-th prime
- Prime generation checks candidates up to `p`
- Each primality test takes up to `O(sqrt(p))`

So total complexity is roughly:

- **Time:** `O(p * sqrt(p))` in the simple version
- **Space:** `O(1)`
