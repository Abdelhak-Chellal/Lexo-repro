### 1) Understand the Test Suite

The function appears to be:

- `prev_prime(n)`

It returns the **largest prime number strictly less than `n`**.

From the examples:

- `f(3) = 2` → largest prime below 3 is 2
- `f(4) = 3`
- `f(5) = 3`
- `f(10) = 7`
- `f(100) = 97`

So the function is **not** returning `n` itself even if `n` is prime; it returns the previous prime.

### Input validation behavior

The tests show two kinds of errors:

1. **Type error** if `n` is not an `int`
   - `'3'`, `3.0`, `None`, `[3]`, `[4, 5]`
   - Error message:
     - `prev_prime() expect parameter n to be int. Given: <type>.`

2. **Value error** if `n <= 2`
   - `2`, `1`, `0`, `-7`
   - Also `True` is treated as invalid here, even though in Python `bool` is a subclass of `int`. The test suite expects it to fail as “larger than 2”.
   - Error message:
     - `prev_prime() expect parameter n to be larger than 2. Given: X.`

### 2) Analyze the Problem

We need an algorithm that:

- Validates that `n` is an actual integer type, not a string/float/list/etc.
- Rejects booleans explicitly.
- Requires `n > 2`.
- Finds the greatest prime smaller than `n`.

This is essentially:
- Decrement from `n - 1` down to `2`
- Return the first prime encountered

Since the test values are modest, a simple primality test is enough. Complexity:

- Outer search: up to `O(n)` in worst case
- Each primality check: `O(sqrt(n))`
- Overall worst case: `O(n sqrt(n))`

This is acceptable for typical unit-test-sized inputs.

---

### 3) Design the Algorithm

#### Step-by-step approach

1. **Type check**
   - If `n` is not of type `int`, raise:
     - `TypeError("prev_prime() expect parameter n to be int. Given: <type>.")`
   - Also explicitly reject `bool` if needed, because `isinstance(True, int)` is `True` in Python.

2. **Range check**
   - If `n <= 2`, raise:
     - `ValueError("prev_prime() expect parameter n to be larger than 2. Given: n.")`

3. **Search downward**
   - Set `candidate = n - 1`
   - While `candidate >= 2`:
     - If `candidate` is prime, return it
     - Otherwise decrement `candidate`

4. **Primality test**
   - For a number `x`:
     - Return `False` if `x < 2`
     - Return `True` if `x == 2`
     - Return `False` if `x` is even
     - Check odd divisors from `3` to `sqrt(x)`:
       - If any divide `x`, return `False`
     - Otherwise return `True`

---

### 4) Handle Edge Cases

#### Important edge cases
- `n = 3` → return `2`
- `n = 4` → return `3`
- `n = 5` → return `3`
- `n = 6` → return `5`
- `n = 8` → return `7`
- `n = 100` → return `97`

#### Invalid inputs
- `n = True`
  - Must raise the “larger than 2” error, not type error, based on the test suite.
  - So the implementation should treat `bool` as invalid for the numeric requirement.
- Non-integer types should raise the type error exactly as specified.

## Algorithm Summary

```text
prev_prime(n):
    if n is not a real int or n is bool:
        raise TypeError("prev_prime() expect parameter n to be int. Given: <type>.")

    if n <= 2:
        raise ValueError("prev_prime() expect parameter n to be larger than 2. Given: n.")

    candidate = n - 1
    while candidate >= 2:
        if is_prime(candidate):
            return candidate
        candidate -= 1
```

Where:

```text
is_prime(x):
    if x < 2: return False
    if x == 2: return True
    if x % 2 == 0: return False
    for d from 3 to floor(sqrt(x)) step 2:
        if x % d == 0:
            return False
    return True
```
