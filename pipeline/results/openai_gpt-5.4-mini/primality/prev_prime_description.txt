### 2) Analyze the Problem

We need an algorithm that, given an integer `n`, returns the greatest prime number `< n`.

This is the classic **previous prime** problem.

#### Observations
- The answer is always a prime.
- The answer is always less than `n`.
- If `n` is prime, we must not return `n`; we return the prime just before it.
- For small values:
  - `f(2)` or `f(1)` would be undefined if we require a prime strictly less than `n`.
  - The smallest valid output in the test suite is `2` for input `3`.

#### Complexity
A simple approach is to test candidates below `n` for primality until one is found.
- Worst-case time: about `O(n sqrt(n))` if done naively.
- Can be improved by checking only odd numbers and using an efficient primality test.

---

### 3) Design the Algorithm

#### Step-by-step approach
1. Start from `n - 1`.
2. Decrease by 1 until a prime is found.
3. Return that prime.

#### Primality test
To check whether a number `x` is prime:
- If `x < 2`, it is not prime.
- If `x == 2`, it is prime.
- If `x` is even, it is not prime.
- Otherwise, test odd divisors from `3` up to `sqrt(x)`.

#### Pseudocode
```text
function f(n):
    x = n - 1
    while x >= 2:
        if isPrime(x):
            return x
        x = x - 1

function isPrime(x):
    if x < 2:
        return false
    if x == 2:
        return true
    if x % 2 == 0:
        return false
    for d from 3 to floor(sqrt(x)) step 2:
        if x % d == 0:
            return false
    return true
```

### 4) Handle Edge Cases

#### Edge cases to consider
- `n <= 2`: no prime exists below `n`
  - Example: `f(1)`, `f(2)` are undefined under this interpretation.
- `n = 3`: return `2`
- `n` itself prime: still return the previous prime
  - Example: `f(17) = 13`
- Very large `n`: naive primality checking may be slow; for efficiency, a sieve or probabilistic primality test could be used depending on constraints.
