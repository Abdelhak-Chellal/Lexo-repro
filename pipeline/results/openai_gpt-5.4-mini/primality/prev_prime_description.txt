- **Output:** the **largest prime number strictly less than `n`**
- **Name hinted by errors:** `prev_prime()`

Validation behavior:

  - `prev_prime() expect parameter n to be int. Given: <type>.`
- If `n` is an integer but `n <= 2`, raise:
  - `prev_prime() expect parameter n to be larger than 2. Given: <value>.`

Important nuance:
- `True` is treated as invalid in this suite, even though in Python `bool` is a subclass of `int`. So the algorithm should explicitly reject booleans as non-integers.

### 2) Analyze the problem

We need to compute the **previous prime** for a given integer `n > 2`.

A prime is a number greater than 1 with no positive divisors other than 1 and itself.

Constraints inferred:
- Must validate type first.
- Must validate range second.
- Must handle edge cases with specific exception messages.

Time complexity goal:
- A straightforward primality test is sufficient for the observed scale.
- For each candidate, test divisibility up to `sqrt(candidate)`.

---

### 3) Design the algorithm

#### Step-by-step approach

1. **Validate type**
   - Reject values that are not of type `int`.
   - Also reject `bool` explicitly.
   - Raise:
     `prev_prime() expect parameter n to be int. Given: <type>.`

2. **Validate value**
   - If `n <= 2`, raise:
     `prev_prime() expect parameter n to be larger than 2. Given: <n>.`

3. **Search downward**
   - Start from `candidate = n - 1`
   - Decrease `candidate` until a prime is found

4. **Primality test**
   - A number `x` is prime if:
     - `x >= 2`
     - no integer divisor from `2` to `floor(sqrt(x))` divides `x`
   - Since we search downward from `n-1`, the first prime found is the answer.

---

### 4) Handle edge cases

- `n = 3` → returns `2`
- `n = 2`, `0`, `-1` → range error
- `n = 2.5`, `'3'`, `None`, `[3]` → type error
- `n = True` → should be treated as invalid type despite being an `int` subclass in Python
- Large numbers: algorithm still works, though not optimized for very large inputs

---

## Algorithm in pseudocode

```python
def prev_prime(n):
    # Type validation
    if type(n) is not int:
        raise TypeError(f"prev_prime() expect parameter n to be int. Given: {type(n)}.")
    
    # Range validation
    if n <= 2:
        raise ValueError(f"prev_prime() expect parameter n to be larger than 2. Given: {n}.")
    
    # Helper to test primality
    def is_prime(x):
        if x < 2:
            return False
        if x == 2:
            return True
        if x % 2 == 0:
            return False
        
        i = 3
        while i * i <= x:
            if x % i == 0:
                return False
            i += 2
        return True
    
    # Search backwards
    candidate = n - 1
    while candidate >= 2:
        if is_prime(candidate):
            return candidate
        candidate -= 1
```

---

## Complexity

Let `n` be the input.

- **Primality check:** `O(sqrt(k))` for each candidate `k`
- **Worst-case search:** potentially checks many numbers below `n`
- Overall worst-case: roughly `O(n * sqrt(n))` in the naive form

For the given tests, this is more than sufficient.

## Final description of the function

The function validates that `n` is a true integer greater than 2, then returns the largest prime strictly smaller than `n`. If the input is not an integer, or if `n <= 2`, it raises the corresponding formatted error.
