### 1) Understand the test suite

The function `f` takes:

- a **list-like first argument** (the main array)
- one or more **extra arguments** that act like “things to remove”

From the examples, `f` returns a new list containing items from the first list **with some values removed**.

Important observations:

- Removal is based on **strict equality**, not type-coercing equality:
  - `1` is **not** equal to `'1'`
  - `0` is **not** equal to `False`
  - `None` and `''` are distinct
- If a removal value is not present, nothing happens.
- If the second argument is:
  - `[]`, `None`, or a non-list scalar like `5`, then it is treated as a single value or ignored depending on whether it can meaningfully represent removals; the tests suggest it does **not** remove anything unless it matches elements by strict equality.
- Multiple removal arguments are combined: remove all values appearing in any of them.
- Duplicate values in the removal lists do not matter beyond the first match.
- The operation removes **all occurrences** of a matching value from the input list.

---

### 2) Analyze the problem

This is essentially a **filtering / set-difference** problem on a list, but with these nuances:

- The input list may contain duplicates.
- Removal targets may be:
  - lists
  - `None`
  - scalars
  - nested objects like lists/dicts
- Equality should be **deep/value equality** as used by normal language equality for those structures, but not coercive:
  - `[1]` matches `[1]`
  - `{'a': 1}` matches `{'a': 1}`
  - `[1]` does not match `[[1]]`
- Removal is performed against **all provided removal arguments**, flattening the effect of each argument into a single removal set.

So the algorithm should:

1. Interpret each extra argument as one or more values to remove.
2. Compare each element of the first list against all removal values.
3. Keep only elements that do not match any removal value.

---

### 3) Design the algorithm

A straightforward algorithm:

#### Step A: Collect removal values
- Initialize an empty collection `R`.
- For each extra argument:
  - If the argument is a list/iterable of removal candidates, add each candidate to `R`.
  - If it is `None`, ignore it.
  - If it is a scalar or non-list object, treat it as a single removal candidate only if the test behavior indicates it should be considered; the suite suggests non-list non-matching values simply cause no removals unless they exactly match an element.

Given the examples, the safe interpretation is:

- If an extra argument is a list, use its elements as removal values.
- If an extra argument is not a list, treat it as a single value to compare against list elements.
- If it is `None`, it does not remove anything.

#### Step B: Filter the input list
- Create result list `out = []`.
- For each element `x` in the first list:
  - If `x` equals any value in `R`, skip it.
  - Otherwise, append `x` to `out`.

#### Step C: Return result
- Return `out`.

---

### 4) Handle edge cases

#### Duplicate removals
Example:
- `f([1, 2, 2, 3], [2, 2]) = [1, 3]`

So duplicates in removal arguments should not affect correctness.

#### Mixed types
Example:
- `f([1, '1', True, False], [True, '1']) = [1, False]`

So comparisons must be exact, not coerced.

#### Nested structures
Examples:
- `f([[1], 2, 3], [[1]]) = [[1], 2, 3]`
- `f([{'a': 1}, 2], [{'a': 1}]) = [{'a': 1}, 2]`

This indicates that nested lists/dicts are compared by structural equality, but only exact matching structures are removed.

#### Empty / null removal inputs
- `f([1, 2, 3], []) = [1, 2, 3]`
- `f([1, 2, 3], None) = [1, 2, 3]`

So empty or absent removal means no change.

#### Multiple removal arguments
Examples:
- `f([1, 2, 3], [2], [3]) = [1]`
- `f([1, 2, 3], [2], None) = [1, 3]`
- `f([1, 2, 3], [2], [2, 3]) = [1]`

So all extra arguments are merged logically.

---

### Algorithm in pseudocode

```text
function f(arr, *removals):
    remove_values = empty list

    for each r in removals:
        if r is None:
            continue
        if r is a list:
            append all elements of r to remove_values
        else:
            append r to remove_values

    result = []
    for x in arr:
        if x is equal to any value in remove_values:
            continue
        result.append(x)

    return result
```

---

### Complexity

Let:
- `n = len(arr)`
- `m = total number of removal candidates`

Using a simple scan, time complexity is:

- **O(n × m)**

Space complexity:

- **O(m)** for storing removal values
- **O(n)** for the result

If optimized with a hashable set, complexity could improve, but because inputs may include unhashable values like lists/dicts, a linear comparison approach is the most general and safest.

---

### Final inferred behavior

`f` removes from the first list every element that appears in any of the subsequent arguments, using strict structural equality, preserving order of the remaining elements.
