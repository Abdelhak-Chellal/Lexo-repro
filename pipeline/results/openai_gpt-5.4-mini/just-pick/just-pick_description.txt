### 1) Understand the Test Suite

The function `f` takes:

- a **source object/array** `obj`
- a list of **keys/indices to keep**

and returns a new object containing only the selected entries from `obj`.

From the tests:

- It works with **plain objects**
- It also works with **arrays**, treating indices as string keys:
  - `[1,2,3]` + `['0','2']` → `{'0':1,'2':3}`
- It preserves the **order of the requested keys**
- Duplicate requested keys are ignored in the output because object keys are unique
- Missing keys are skipped
- Non-string keys in the key list are ignored (`1`, `True`, `None`)
- If the key list is provided as separate arguments, it behaves the same as if they were in an array
- Nested values are copied as-is, not deep-cloned
- `null` source causes a membership check error
- `null` key-list causes a length-access error

---

### 2) Analyze the Problem

This is essentially a **selective shallow projection** / **pick** function:

- Input:
  - `obj`: object or array
  - `keys`: either an array of keys or variadic key arguments
- Output:
  - a new object containing only properties from `obj` whose keys are requested and exist in `obj`

Important observations:

- For arrays, numeric indices are accessed as string keys
- The function does **not** recurse
- It does **not** include invalid key types
- It respects the order of the requested keys, not the order of the original object
- It does not throw for missing keys, only for invalid input such as `null` in the source or key-list position

---

### 3) Design the Algorithm

#### High-level idea
Normalize the key input into a single array of keys, then iterate over it and copy matching properties from the source into a new result object.

#### Step-by-step
1. **Normalize keys**
   - If the second argument is already an array, use it directly.
   - Otherwise, treat all arguments after the first as the key list.

2. **Create an empty result object**

3. **For each key in the key list**
   - Ignore it unless it is a string
   - Check whether the key exists in the source object/array
   - If yes, copy `source[key]` into the result under the same key

4. **Return the result**

#### Why this matches the tests
- Preserves order of requested keys by iterating over them in order
- Skips keys not found in source
- Works for arrays because array indices are accessible as string keys
- Duplicate keys overwrite with the same value, leaving the same final property once
- Ignores non-string keys

---

### 4) Handle Edge Cases

#### Covered by tests
- Empty key list → `{}`  
- Empty source object → `{}`
- Missing keys → skipped
- Duplicate keys → only one result property
- Array source → indices treated as strings
- Nested objects → returned by reference, no recursion

#### Additional likely edge cases
- If `obj` is `null` or `undefined`, membership checking should fail as shown
- If the key list is `null`/`undefined`, accessing its length should fail as shown
- If keys are symbols or other non-string types, they should be ignored
- If source has inherited properties, behavior depends on whether membership is checked with `in` or direct property access; the test suite strongly suggests an `in`-style check or equivalent

---

### Suggested Algorithm in Pseudocode

```text
function f(obj, ...args):
    if args.length == 1 and args[0] is an array:
        keys = args[0]
    else:
        keys = args

    result = empty object

    for key in keys:
        if type of key is not string:
            continue
        if key exists in obj:
            result[key] = obj[key]

    return result
```

---

### Complexity

Let:

- `n` = number of requested keys

Then:

- **Time:** `O(n)`
- **Space:** `O(k)` for the output, where `k` is the number of copied entries

---

### Final Description

The function is a **shallow pick/projection utility** that returns a new object containing only the string-keyed properties from the input object/array whose names are listed in the key arguments, preserving the requested order and ignoring missing or invalid keys.
